# Qwen Tunnel Runbook

The Qwen endpoint is a Run:ai workload (`qwen38-27b12`, project `romania-dev`) reached
through a local port-forward chain. Everything binds to `127.0.0.1`.

## Components

| component | location | role |
| --- | --- | --- |
| runai CLI | `.runai-cli/bin/runai` | authenticates to the cluster, port-forwards the workload |
| Caddy | `.caddy/bin/caddy` | local reverse proxy `127.0.0.1:19080` -> cluster ingress `10.130.240.221` (SNI `cisco-ai-pod.cc-demos.com`) |
| supervisor | `scripts/qwen_tunnel_supervisor.sh` | keeps both alive, health-checks every 5 s |
| runai auth | `/home/jovyan/.runai/authentication.json` (pod home, NOT on PVC) | CLI token + refresh token |
| proxy auth copy | `/home/jovyan/.runai-proxy/` | generated by the supervisor |

Endpoint: `http://127.0.0.1:18000/v1`, model `Qwen/Qwen3.8-27B-FP8`.

## Operations

```bash
cd /home/jovyan/work/causal-mind
scripts/qwen_tunnel_supervisor.sh status    # RUNNING + QWEN HEALTHY expected
scripts/qwen_tunnel_supervisor.sh start

bash scripts/test_qwen_proxy.sh             # end-to-end proxy test

```

## Token expiry (known contingency)

The runai CLI access token is short-lived (24 h) but a refresh token is stored. The
supervisor waits and retries if `auth get-token` fails. **If the refresh token itself
stops working**, the tunnel will log `waiting for Run:ai authentication` and the
endpoint goes unhealthy. Human action required:

1. In the pod (as jovyan): `~/.runai-cli/bin/runai login remote-browser` (or the
   project-local `.runai-cli/bin/runai login remote-browser`).
2. Follow the printed URL in a browser, complete SSO.
3. `scripts/qwen_tunnel_supervisor.sh status` should return to `QWEN HEALTHY` within
   ~30 s.

Never print or commit the token. It lives only in `/home/jovyan/.runai` and
`/home/jovyan/.runai-proxy` (mode 600).
